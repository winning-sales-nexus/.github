# AI slop — what makes nexu-fe look machine-generated

Visual and copy patterns that mark an interface as "generated by an agent". nexu is a **product**
(a tool sellers and leaders open every day), so restraint is the default: none of these is
tolerated as decoration. Adapted from the Impeccable catalog (impeccable.style/slop), trimmed to
what applies to this repo and reconciled with the tokens and utilities in `src/index.css`.

ESLint already blocks raw colours (`bg-[#...]`, `rgb(`, `oklch(`...), so the classic "AI palette"
(purple/violet + cyan) can only enter through a new token. A new token needs a stated purpose
(SKILL.md), and "looks modern" is not one.

## How to use it

1. **While building**: check the screen against this list before calling it done. A match means
   revising, not justifying.
2. **In review**: the `[grep]` rules have a command at the end; the `[look]` rules need the screen
   rendered (`npm run dev`, both themes).
3. **Sanctioned exceptions** are listed per rule. Anything outside them is a finding.

## Surfaces and containers

**SL-01 Side accent border on a card** `[grep]`
A thick coloured stripe on one side of a `Card` (`border-l-4 border-l-*`). It is the most
recognisable generated-UI tell. Bring the colour inside: a `Tag`, a dot, a coloured title or
icon. *Not this rule*: the 2px neutral rule used as a quote/annotation marker
(`border-l-2 border-rule pl-3`, as in `quote-line.tsx`), timeline markers and dashed chart guides.

**SL-02 Border and wide shadow on the same element** `[grep]`
A hairline `border` plus `shadow-xl`/`shadow-2xl`. Pick one edge treatment. Cards use
`surface-card` / `shadow-card`, menus `shadow-menu`; there is no bigger shadow in the system.

**SL-03 Glass and glow as ornament** `[grep]`
`backdrop-blur`, translucent white fills and coloured `box-shadow` glows. The only sanctioned glass
is `glass-card` **on top of** `hero-panel` / `dark-block` (dark hero blocks: auth, recording, home
highlight cards). Glass on a light surface, or on a plain card, is a finding. Dark mode gets
depth from lighter surfaces (the token flip), never from glows.

**SL-04 Cards inside cards** `[look]`
A `Card` (or `surface-card`) nested in another one. Separate the inner content with spacing,
a `label-caps` heading or a `border-rule-soft` divider.

**SL-05 Over-rounding** `[grep]`
`rounded-2xl`/`rounded-3xl` on cards and controls. Use `rounded-card` and `rounded-control`;
`rounded-full` only for pills, avatars and dots.

**SL-06 Decorative patterns and gradients** `[grep]`
Gradients and repeating stripes as surface decoration. Sanctioned: `hatched` (a data-viz encoding
in charts, e.g. undeclared forecast), `channel-art-*`, `hero-panel`, `dark-block`, `anti-block`,
`chat-backdrop`. Chart hatching written inline (`bg-[repeating-linear-gradient(...)]`) should move
to `hatched`. A new decorative gradient is a new utility in `index.css` with a stated purpose,
never an inline `bg-gradient-*`.

**SL-07 Gradient text** `[grep]`
`bg-clip-text` + gradient on a heading or a number. Never in product: it kills scannability
precisely on the figures people read the most. Solid `text-ink` / `text-brand`.

## Layout

**SL-08 Identical card grid** `[look]`
Three or four same-size cards, each with an icon tile stacked above a heading and a sentence.
This is the default generated homepage. Lead with the data: a table, a list, a `KpiTile` row or
one emphasised block plus supporting ones.

**SL-09 Icon tile above a heading** `[look]`
A rounded-square container holding an icon, sitting above every card title. Put the `lucide-react`
icon inline with the title, or drop it.

**SL-10 Template metric hero** `[look]`
Big number + small label + three supporting stats + a gradient, with no comparison or meaning.
A figure on screen carries context: period, comparison or target (`BigKpi` with its delta,
`Gauge` with the goal). If there is nothing to compare against, it probably does not deserve the
hero size.

**SL-11 Monotonous spacing** `[look]`
The same gap everywhere (`gap-4` on every level). Related items sit closer than unrelated ones:
tight inside a group, wider between groups, widest between sections. Inner padding is never
larger than the gap outside the container.

**SL-12 Clipped popovers and long lines** `[look]`
Menus/tooltips cut by an `overflow-hidden` ancestor: use the Radix portal that the `shared/ui`
wrappers already provide, never a hand-positioned absolute box. Running text wider than ~75
characters gets a `max-w-*` (prose reads at `65ch`–`75ch`).

## Typography

**SL-13 Flat hierarchy** `[look]`
A screen where the title, the section headings and the body are within a step of each other on the
scale. Hierarchy comes from size **and** weight; use the tokenised scale (`text-2xs`…`text-5xl`)
and `font-display` for titles, never arbitrary sizes (`text-[13px]` is `text-sm`).

**SL-14 Tracking and caps on running text** `[grep]`
`uppercase` or wide tracking on sentences, `tracking-tighter` on body. Caps belong to short labels:
that is what `label-caps` is for (a few words, not a paragraph).

**SL-15 Tiny running text** `[look]`
`text-2xs` (11px) and `text-xs` (12px) are for labels, captions, badges and chart ticks. A sentence
the user must read and understand is `text-sm` (13px) or larger.

## Motion

**SL-16 Bounce, elastic and layout animation** `[grep]`
Overshooting easings (`ease-in-back`, elastic `cubic-bezier`) and animating `width`/`height`/
`padding`/`margin`. Enter with ease-out, leave with ease-in, short (150–250 ms), using `transform`
and `opacity`. Sanctioned: `Progress` and the recording level meter animate width/height because
the value **is** the size; keep them short and with `motion-reduce:transition-none`.

**SL-17 Hover scale/rotate on content** `[grep]`
`hover:scale-*` / `hover:rotate-*` on images and cards. Hover feedback is a background step
(`hover:bg-surface-2`) or a border change.

## Copy (pt-BR)

Copy lives in `*-copy.ts`; review it there.

**SL-18 Em-dash cadence** `[grep]`
Sentences stitched together with "—". One in a while is fine; a habit is the tell. Prefer a
period, a comma, a colon or parentheses.

**SL-19 Marketing buzzwords** `[grep]`
"potencialize", "alavanque", "revolucione", "turbine", "de ponta", "sem esforço", "incrível",
"poderoso", "experiência única", "insights valiosos". Say what the screen does with concrete verbs
and nouns from the sales domain ("3 negócios sem próxima ação", not "insights poderosos sobre
seu pipeline").

**SL-20 Aphorisms and manufactured contrast** `[look]`
"Não é X. É Y.", "Menos X, mais Y.", closing taglines on cards and empty states. State the fact and
the action. The empty state says what fills it and offers that action (SKILL.md, four states).

## Quick scan

Run from the repo root; review every hit against the exceptions above.

```bash
# SL-01 accent stripe on a card
grep -rEn "border-l-[48]|border-r-[48]" --include=*.tsx src
# SL-02 border + wide shadow / SL-05 over-rounding
grep -rEn "shadow-(xl|2xl)|rounded-(2xl|3xl)" --include=*.tsx src
# SL-03 glass and glow outside the dark hero blocks
grep -rEn "backdrop-blur|glass-card|shadow-\[.*(rgb|color-mix)" --include=*.tsx src
# SL-06 / SL-07 gradients and gradient text
grep -rEn "bg-gradient|bg-linear|bg-radial|bg-clip-text|repeating-linear" --include=*.tsx src
# SL-14 caps/tracking on running text
grep -rEn "tracking-tighter|<p [^>]*uppercase" --include=*.tsx src
# SL-16 / SL-17 motion
grep -rEn "transition-\[(width|height|padding|margin)|ease-(in|out)-(back|elastic)|hover:(scale|rotate)-" --include=*.tsx src
# SL-18 em-dash count per copy file
grep -rc "—" --include=*-copy.ts src | grep -v ":0$" | sort -t: -k2 -nr | head
# SL-19 buzzwords
grep -rEni "potencializ|alavanc|revolucion|turbin|de ponta|sem esforço|incríve|poderos|experiência única|insights valiosos" --include=*-copy.ts src
```
